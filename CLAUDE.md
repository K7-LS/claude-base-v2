# Claude Base

Отвечай на языке пользователя. Имена файлов, команд и параметров сохраняй в
исходной форме.

## Рабочий режим

- Простой разговор и короткое объяснение выполняй без инструментов, subagents
  и reviewer-процедур.
- Существенное изменение начинай с проверки реальных файлов и нативного
  `Plan Mode`. Отдельный brainstorming workflow не запускай.
- Загружай полный skill только после совпадения задачи с его кратким
  описанием. Supporting files читай только по необходимости.
- Детерминированную обработку выполняй скриптом раньше LLM. Не запускай
  массовую делегацию по умолчанию.

## Маршрутизация

- Расчёты и подбор инженерного оборудования → `designer`.
- Объёмы, ВОР и спецификации → `pto-engineer`.
- Сметы и КС-2/КС-3 → `smetchik`.
- Снабжение и УПД → `snabzhenets`.
- Исполнительная документация → `id-engineer`.
- Точная нормативная цитата → `norm-lookup`; не цитируй нормы по памяти.
- Один раздел по нормам → `audit-rd-section`; несколько разделов →
  `rd-coordinator`.

Reviewer нужен для выдаваемых документов, количеств, нормативных ссылок и
дорогих либо необратимых решений. Форму проверяет профильный reviewer,
содержание по источникам — `auditor`. Обычный ответ и диагностика reviewer не
требуют. Недоступное для проверки не является PASS.

## Инструменты, данные и обновление

- Внешние tools, MCP и plugins активируй только по зависимости выбранного
  skill и с разрешения, если требуется установка или вход.
- Модель и effort базой не задаются.
- Не изменяй авторизацию, сессии, историю, plugins, проекты и рабочие папки.
- Обновления идут только hub → consumer. Проверка версии молчит, если новой
  стабильной версии нет; установка запускается только через `$sync-base`.
- Никакие сессии, документы, локальные изменения и учётные данные обратно не
  отправляются.
